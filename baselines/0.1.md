# Web Prolog interoperability baseline 0.1

Status: **scoped draft, 2026-10-21**. This baseline covers selected public
interfaces of the existing native SWI, native Trealla, SWI-WASM Worker/main
engines and GNU Prolog ISOBASE node. It is not certification of the complete
language, all supported predicate modes, ISO conformance, security containment
or every lifecycle interleaving. No new runtime semantics are introduced here.

## Authority and versions

The shared [language manual](https://github.com/torbjornlager/trinity-demonstrator/blob/main/web/manual.html)
is the language reference; Appendix B presents that same language, not a
separate runtime contract. This baseline selects explicit observable obligations
and connects them to tests. Runtime READMEs own mechanisms, setup and limitations.
SWI is a candidate under test, not an authority that overrides an agreed rule.

GNU's [ISOBASE contract 0.2.0](https://github.com/torbjornlager/gprolog-port/blob/main/isobase/contracts/0.2.0/CONTRACT.md)
and [reconciliation inventory](https://github.com/torbjornlager/gprolog-port/blob/main/isobase/STATUS.md)
remain separate, broader draft obligations. Passing these ten HTTP cases neither
supersedes that contract nor resolves its numeric, option, text or address
requirements. The [difference register](../docs/BASELINE_DIFFERENCES.md) records
the boundary. Required failures in either contract must not become passes by
being labelled diagnostic in another report.

Three versions have different purposes:

- **Baseline 0.1:** this selected agreement and its requirement/test inventory.
- **Wire protocol 1:** existing compatible HTTP/actor vocabulary; capability
  negotiation is additive and does not increment it.
- **Report schema 2:** the new endpoint-neutral evidence format. Existing
  schema-1 ACTOR reports and their runner remain unchanged and readable.

Once a baseline is frozen, a normative change needs a new baseline/pack version.
Corrections to fixtures must identify the reason and affected evidence; never
rewrite old reports to manufacture a pass. A disputed requirement is recorded
for a decision. Host-specific error context or pid formatting is not promoted
to a language rule merely because one implementation produces it.

## Applicability

| Surface | Native SWI | Native Trealla | GNU Prolog | SWI-WASM Worker/main |
|---|---|---|---|---|
| ISOBASE HTTP `/call` pack | Required | Required | Required | Not a server surface; not applicable |
| Local ACTOR language assertions | Required | Required | Outside ISOBASE; not applicable | Required, through test-only engine adapter |
| HTTP client paging/promise pack | Required when outbound target is granted | Same | Same, with owner origin/IP grants | Not measured in this batch |
| Cross-node ACTOR pack | Required for the tested actor routes | Same | Outside ISOBASE | Not measured in this batch |
| Actor wire/capability pack | Required for the stated capabilities | Same | Outside ISOBASE | Browser engine is not a `/ws` server |

These test packs are not new advertised node profiles. Existing `relation`,
`isobase`, `isotope` and `actor` distinctions remain. A lower-profile node is not
broken because an ACTOR case is inapplicable. Conversely, a required operation
that fails is **fail**, not an optional capability retroactively removed.
ISOTOPE's complete HTTP-session surface and RELATION are outside this batch.

## Shared observations

1. Portable fixtures use acyclic ordinary Prolog terms: atoms, finite numbers,
   variables, lists and compounds. Repeated variables must remain shared, and
   distinct variables must not be merged. Attributed variables, streams, blobs,
   cyclic terms and host module databases are not covered.
2. Pids and references are opaque on the language surface. Equality, identity
   and monitor matching are tested inside Prolog, without decimal-width tests.
   A transport can specify an encoding without making its representation a
   language guarantee. Main-thread browser identity is permitted.
3. Successful requests return answer terms/bindings; logical failure and
   exceptions remain distinct. Error contexts and prose are not compared where
   no shared context format is specified. Literal exception payloads are checked.
4. Submitted source is request-private on stateless HTTP calls. Successful
   loading, answer projection and absence from a later request are separate
   observations. Source-fetch policy and loading machinery remain runtime concerns.
5. Positive finite page limits, offsets and `once(true)` must produce the listed
   slices without skipping answers. Page flags must match the specified finite
   fixture outcomes; deterministic final fixture pages must report false. This
   selection makes no further decision about unknown residual choicepoints.
   No test demands a lookahead solution with
   side effects. Cache ownership, expiry and reclamation algorithms are excluded.
6. Selective receive retains unmatched messages and failed-guard messages.
   Worker and synchronous-wrapper fixtures have exactly one observable result;
   fixtures do not add `once/1` to hide extra alternatives.
7. Remote source/goal execution uses the receiver's execution context, preserves
   query/template sharing and canonical asynchronous answer payloads, and
   delivers requested termination notifications. Unrelated application messages
   and monitors remain available.
8. `web-prolog-sync-spawn-v1` advertises both synchronous query correlation and
   IDs on spawn successes/failures. `web-prolog-sync-v1` promises only query
   correlation. Unnegotiated legacy spawning remains possible; untagged command
   errors there remain ambiguous. A selected capability is checked, not inferred
   from the existence of an endpoint or a different capability.
9. Timeouts and connection loss are not remote cancellation. Loss during
   creation can leave its outcome unknown. No blanket no-orphan guarantee is
   made. In particular, Trealla `lineage_close` support remains separate.

## Executable obligations and traceability

| Pack | Stable IDs | Requirement / provenance |
|---|---|---|
| [ISOBASE HTTP](../cases/isobase-http-0.1.json) | IB-001–010 | `/call` success/failure/error, pages/offset/once, source, sharing and JSON. Extracted from GNU `isobase/http_tests.py` and both native HTTP suites. |
| [ACTOR language](../cases/language-actor-0.1.json) | LC-001–007 | Opaque identity, receive, workers and synchronous wrappers; same goal strings on native and browser engines. Existing worker/wrapper runtime tests are provenance, not imported runtime internals. |
| [HTTP interoperability](../cases/interop-http-0.1.json) | HC-001–002 | RPC page enumeration and promise template/caller independence, across all three HTTP implementations. GNU `rpc_tests.py` and native client regressions. |
| [ACTOR interoperability](../cases/interop-actor-0.1.json) | IX-001–003 | Public remote constructor, source, synchronous pages, canonical async terms and monitor preservation. Native synchronous/remote-creation regressions. |
| [Wire capabilities](../cases/wire-capabilities-0.1.json) | WP-001–003 | Negotiated spawn IDs and unrelated errors, old query subprotocol, and unnegotiated legacy receiver behavior. Native correlation transport and Trealla spawn-reply regressions. |

Every row is implemented by `runner/baseline.py`, except browser execution of
LC fixtures, which uses `adapters/wasm.cjs` and a test-only engine setup export.
HTTP operator goals/templates are parenthesized identically for all candidates.
Ground terms and sharing are compared lexically over the limited ordinary-term
fixture subset, normalizing variable names by first occurrence. This is not a
complete Prolog parser; it never erases aliasing or quoted text.

Existing ACTOR Core/Workers/Behaviours/Supervisors 0.1 suites are run and reported
as **supporting, separately versioned contracts**. They retain their own scope
and historical IDs. The old ACTOR Core identifier-width assertion is not adopted
by this baseline; LC-001 is the baseline identity requirement. See their profile
files for their additional obligations. Passing our selection cannot certify
omitted startup races, resource quotas or every supervisor strategy/interleaving.

## Diagnostics and evidence

[ISOBASE observations](../cases/isobase-diagnostics-0.1.json), existing worker and
supervisor diagnostics, and experimental Portable Text are separate reports.
Unresolved facts are preserved, not normalized away. A diagnostic observation
is neither a required pass nor a waiver of a required failure. A diagnostic
transport failure means the observation was not obtained, not a semantic result.

The [coverage matrix](../reports/2026-10-21-baseline-0.1/COVERAGE.md) links raw
reports, candidate source/binary identities, configuration, untested cells and
known failures. Supporting-suite failures remain visible in their own totals.
Browser checks use real SWI-WASM engines with a test coordinator under Node;
they establish these local language observations, not browser UI, CORS, fetch,
real-network or complete ACTOR-server conformance.

For reproduction and extensions see [the runner guide](../docs/BASELINE_RUNNER.md).
