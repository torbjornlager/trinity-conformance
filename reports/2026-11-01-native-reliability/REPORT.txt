Native reliability follow-up — 1 November 2026
=============================================

This follows the retained failures in ../2026-11-01-source-copying-release/REPORT.txt.
The earlier record and its failed observations are unchanged. All work here used
archived sources and disposable containers. Public services, their images and
installed engines were unchanged. No PDF or layout checks were performed.

Changes
-------
1. Trealla preserves a committed exit at mailbox boundaries, including between
   protected native wait slices. Catching the unwind token cannot admit another
   receive or timeout callback. Ordinary caught exceptions still permit receiving;
   actor finalization does not start another unwind. This addresses actors that
   committed an exit yet resumed waiting, leaving callers waiting for down/3.

2. Trealla connection shutdown runs an owner-side signal that closes and retires
   the connection before unwinding. It avoids native thread_cancel's combination
   of a read-cancellation flag and a queued thread_exit signal. Draining twice is
   idempotent; stream close is protected and performed once. Native-thread handle
   publication and shutdown admission share the lifecycle mutex, eliminating the
   pending-handle handoff race. No installed host engine was patched.

3. The finite-limit connection fixture commits its client work so setup_call_cleanup
   completes before connection-retirement assertions; WebSocket acquisition belongs
   to the protected setup. The original fixture could assert before cleanup ran.

4. SWI supervisor fixtures await each monitor notification independently. Receipt
   of the spawn-time monitor notification does not imply that an additional monitor's
   separately delivered notification is already queued. The old zero-timeout check
   failed in 4/10 focused baseline invocations; all 20 repaired invocations pass.

5. The broad Trealla run exposed the analogous assumption in the delegated-lineage
   fixture. A creator's termination does not establish that a separately preparing
   child has retired. Closure immediately rejects new admission but lets already
   reserved source preparation finish and reject activation. The fixture now snapshots
   remaining actors and observes their monitors under one deadline before asserting
   an empty namespace. This changes the test barrier, not namespace-close semantics.

6. Remote-demonitor failures now identify the failing subtest instead of returning
   an unexplained false. Its originally reported failure was not reproduced; no
   specific root-cause claim is made for that historical observation.

Two new native regressions fail on the unchanged Trealla base and pass after repair:
- actor_exit_wait_tests: caught committed exits cannot resume blocking/poll/timed/
  deadline receives; a caught ordinary exception remains a positive control.
- node_shutdown_tests: a second drain while cleanup is deliberately held cannot
  interrupt cleanup or retain a stale connection record.

The supervisor cleanup test's deliberate post-exit mailbox inspection now reads
its internal diagnostic snapshot directly; it does not resume application receive.
The current node cleanup uses public sig_atomic/1, so the runner requires Trealla
3.14.10 or newer. The local build helper now defaults to the tested v3.14.20.

unchanged seven packs of actor-release-0.1. It passes 44/44 on SWI and 44/44 on
Trealla: 88/88 total. The previous 40-case profile remains explicitly selectable.
The four shared cases also pass on the old sandboxed Trealla node: the existing
public goal rewriting already protects caught control exceptions. The native
counterexample exercises runtime/host paths outside that rewrite. The new public
cases preserve that observable protection; they are not presented as negative
controls for the runtime repair.

On the committed Trealla runtime (170ec3f), every repeated invocation passes:
- finite-limit WebSocket: 200/200;
- remote demonitor: 20/20;
- grouped isolation: 10/10;
- grouped sandbox: 10/10;

These are 250 successful fresh-process invocations, not a statistical reliability
estimate. The original-source 50-invocation control has five sandbox timeouts,
one synchronous-wrapper timeout and one isolation failure. Its other cases pass.
The historical finite-limit WebSocket segfault was not reproduced. Teardown races
were reproduced as premature retirement checks and stale records after native
cancellation. No claim is made that the original crash's precise cause is proven.

All 54 Python runner tests pass. The final full native SWI script passes.
The final full native Trealla unit script also passes, including the corrected
lineage-retirement barrier. Both complete logs and exit observations are retained.
