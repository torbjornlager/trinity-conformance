# ACTOR Core 0.1 draft baseline — 2026-10-02

This report records the first execution of the versioned, black-box
`actor-core-0.1` suite. It is evidence for developing the profile, not a final
conformance certificate.

## Candidates

| Candidate | Runtime/configuration | Result |
|---|---|---:|
| SWI reference node | Local source checkout, `profile(actor)`, open authentication, blacklist sandbox | 7/7 pass |
| Trealla port | Trealla Prolog 3.12.6, local source checkout, `profile(actor)`, open authentication, blacklist sandbox | 7/7 pass |

Both candidates were started as fresh processes and exercised only through
their WebSocket endpoints by `runner/run.py`. Each case used a fresh
connection. No implementation module was imported by the runner.

## Covered cases

- `AC-001` protocol-version and browser-capability negotiation
- `AC-002` deterministic public session identity
- `AC-003` bindings and finite toplevel paging
- `AC-004` arithmetic guarded receive and acknowledged output
- `AC-005` deferred-message selective receive
- `AC-006` direct browser prompt/respond
- `AC-007` nested toplevel prompt/respond through the protocol caller

## Specification finding

The first run exposed a difference in `transport_welcome`: Trealla includes a
`profile` field while the SWI reference node currently omits it. Version 1 of
the shared transport otherwise negotiates the same protocol and browser
capabilities. ACTOR Core 0.1 therefore treats an included profile as
checkable metadata but does not require this optional field. The candidate's
advertised profile is supplied independently to the runner.

This was classified as a specification-boundary finding, not a candidate
failure. It demonstrates why the suite must specify shared observable
behaviour rather than copy either implementation's output wholesale.

## Limits of this baseline

Seven passing cases do not establish full ACTOR conformance. The next
executable tranche should cover monitors and distinct references, explicit
exit and demonitor behaviour, source-bearing sessions, remote spawn/RPC,
connection cleanup and reconnect, resource ceilings, and concurrency/soak
behaviour.
